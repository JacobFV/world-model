# openfigi_mappings

OpenFIGI's answers to "which security is this CUSIP" and "which security is this ticker at this
MIC", as the statements OpenFIGI made.

`sec_13f_history` and `sec_ownership_datasets` publish **87,357,054 holding rows keyed on a CUSIP
and no issuer CIK**. [`docs/firm-panel.md`](../../docs/firm-panel.md) measured what that costs: the
only published route to an issuer — GLEIF's ISIN mapping, read as `ISIN(US/CA) → CUSIP` on the LEIs
that happen to carry a CIK — reaches **1.7% of those rows and 393 issuers, 371 of them funds**. The
follow-up it named is this dataset: OpenFIGI's mapping API turns a CUSIP into a FIGI with a ticker,
and `sec_issuer_reference` already publishes the issuer's `issuer_listing` edges to
`ticker:<MIC>:<symbol>`. The two meet.

## Route

`POST https://api.openfigi.com/v3/mapping`, at most ten mapping jobs per request, at most 25
requests a minute. Both limits are the publisher's own, and both were measured against the service
on 2026-09-19: an eleventh job is refused with `HTTP 413 Request may only contain 10 mapping jobs.`
and every response carries `ratelimit-policy: 25;w=60`. An API key would raise them to 100 jobs and
25 requests per 6 seconds; none is held, so the unkeyed limits are what the declaration honours.

Three request groups, all declared up front in
[`dataset.json`](dataset.json) and generated by [`build_requests.py`](build_requests.py) from
pinned normalized artifacts:

| group | jobs | what it asks | requests |
| --- | ---: | --- | ---: |
| `cusip` | 94,924 | `idType: ID_CUSIP` for every check-digit-valid CUSIP on a 13F information table | 9,493 |
| `ticker_mic` | 7,665 | `idType: TICKER` + `micCode` for every SEC-published symbol whose SEC exchange value is an ISO 10383 MIC (`XNAS`, `XNYS`) | 767 |
| `ticker_us` | 9,859 | `idType: TICKER` + `exchCode: US` for every SEC-published symbol, the only scope available for the ones SEC labels `OTC` or `CBOE` | 986 |

The `micCode` filter is the point of the second group. OpenFIGI publishes Bloomberg's two-character
exchange codes (`UN`, `UW`, `UA`), not MICs, and nothing in this catalog maps one to the other — so
instead of translating, the request carries the MIC and OpenFIGI answers inside it. That is what
makes `figi_ticker` assertable at the scope its mapping specification requires.

**The endpoint answers positionally.** One result per job, in request order, with no echo of the
identifier asked about. A response with a different number of results than its request had jobs
would re-align every following result with the wrong CUSIP, so the pipeline holds every shard to
its request's job count and fails the build otherwise.

### What the CUSIPs are, and what was refused before anything was sent

141,566 distinct CUSIP-shaped values appear on these information tables. **94,924 carry a valid
modulus-10 double-add-double check digit** and are sent; 46,642 do not and are not. The failures
are almost entirely filer-constructed option pseudo-CUSIPs — a 9 in the seventh position,
`037833900` for an Apple call, `78462F953` for an SPDR put — plus placeholders like `000000001`.
They account for 1,382,328 of the 87,357,054 holding rows (1.6%), and the option rows are already
excluded from the ownership aggregate anyway. `000000000` passes the check digit and is refused by
value in [`worldmodel/resolution/openfigi.py`](../../worldmodel/resolution/openfigi.py).

## What is published

One `openfigi_mapping` assertion per row OpenFIGI returned, subject `figi:<FIGI>`, carrying the
query it answers and the published `figi`, `name`, `ticker`, `exchCode`, `compositeFIGI`,
`shareClassFIGI`, `securityType`, `securityType2`, `marketSector` and `securityDescription`.

One `entity` per FIGI, but only at the levels this catalog can meet: the **US composite**
(`exchCode` `US`), an instrument OpenFIGI publishes **no composite** for (a bond, a muni, a
preferred — `NOT LISTED`, `TRACE` or no exchange code), and a **MIC-scoped listing**. A US equity's
Frankfurt, Mexican or Swiss line gets a statement and no entity: nothing else here names it, and a
quarter of a million unreachable securities would be a worse graph, not a bigger one.

Nothing is published as an `identifier_assignment`. The FIGI in an answer is OpenFIGI's own
assignment, but the CUSIP or ticker in it is the **query** — the identifier this catalog asked
about. Turning "OpenFIGI answered this CUSIP with this FIGI" into "this CUSIP is this security" is
a judgement, and it belongs in the resolution layer where a cardinality break is refused and
counted.

## Rights

The [OpenFIGI Terms of Service](https://www.openfigi.com/docs/terms-of-service) dedicate the FIGI
Identifiers to the public domain: they "may be freely reproduced, distributed, transmitted, used,
modified, built upon, or otherwise exploited by anyone for any purpose", and a user is "free, on a
non-exclusive basis, to use, display, reproduce, distribute and create derivative works from the
FIGI Identifiers", expressly including redistribution. No attribution is required and none of the
terms restrict automated access; the published rate limits are honoured instead. The identifiers
and the security descriptions are provided **as is**, with no warranties and liability capped at
US$50, so nothing here is authoritative about a security. The CUSIP values sent as queries are read
out of SEC Form 13F information tables, a U.S. government work.

## Rebuild

```sh
# regenerate the request list from the pinned artifacts (a no-op unless they change)
WORLD_MODEL_DATA=... python3 data/openfigi_mappings/build_requests.py
WORLD_MODEL_DATA=... python3 -m worldmodel acquire openfigi_mappings --allow-network   # ~8 h
WORLD_MODEL_DATA=... python3 -m worldmodel run openfigi_mappings
```
